# CameraViews：透视与正交相机

默认绘制调度间隔为 16ms；实际帧率取决于渲染、显示提交和触摸读取。
输入配置与 UI 共用触摸见 [Interaction.md](../../docs/Interaction.md)。

本例独占整屏，使用 `presenter.presentFit(renderer.frame())` 保持比例，
每帧覆盖整个屏幕并把全部留边填黑；第二个参数可指定 RGB565 背景色。
需要保留外围内容时使用 `present(surface, viewport)`，不要使用整屏填边 API。

两个相机都支持单指拖动和双指捏合，分别保留各自视角；`p` / `o` 切换投影时不重置。
透视捏合改变观察距离，正交捏合改变投影视野；串口 `h` 复位当前相机及其缩放。
两套控制器都使用实际屏幕尺寸映射触摸，切换时重新建立手势，触摸读取在帧门限之前。
启动日志 `Orbit touch probe: ready/unavailable` 报告探测结果。默认适配 P4 JC1060 GT911、
S31 Korvo GT1151；更换板卡时同时配置 `NiceGfxOrbitInput`。

用于产品展示和模型检视的相机入门示例：用一个 `Renderer` 绘制同一场景，
通过串口切换两种相机。透视适合观察模型的空间深度，正交适合比较外形与比例。
本例用三个免素材方块隔离投影差异，方便先理解 API；它不是复杂模型展示的替代品。
三个方块大小和姿态相同，橙色在近处、青色在中间、绿色在远处。

| 串口字符 | 相机 | 观察点 |
| --- | --- | --- |
| `p` / `P` | `PerspectiveCamera`，默认 | 近处物体的投影更大 |
| `o` / `O` | `OrthographicCamera` | 同样大小、姿态的物体具有相同投影大小 |

两台相机使用相同位置和 `lookAt(0,0,0)`，相机朝局部 -Z。
透视 `fov` 的单位为度；正交 `left/right/top/bottom` 的单位与模型坐标相同。
正交视野高度设为 3.6，宽度按内部画布 4:3 计算；透视 `aspect` 也使用内部画布比例。

## 运行

1. 安装 `nice_gfx`、`nice_gfx_3d`，选择实际 P4/S31 板卡及对应 Arduino core、PSRAM 配置。
2. 检查本目录 `Hardware.h`。默认 P4 是 **JC1060P470C_I_W_Y**，默认 S31 是
   **ESP32-S31-Korvo-1**；其他板须替换显示声明为该板真实的 nice_gfx 预设/配置。
3. 打开 `CameraViews.ino`。串口监视器选 115200，发送 `p` 或 `o`；换行会被忽略。
   无需资源文件或模型转换。

切换时只更换 `Camera*`，不会重建场景、Renderer 或缓冲区。
本例内部渲染为 320×240，输出使用 `presentFit()` 保持比例，因此无需把相机比例改成屏幕比例。
若修改投影参数，调用对应相机的 `updateProjectionMatrix()`；如果修改内部渲染宽高，
需同时调整两种相机的投影配置。

用于真实模型检视时，可以用 `Model::scene()` 替代这些方块加入场景，继续复用
`activeCamera` 切换和同一个 Renderer。根据模型的世界单位、中心与包围尺寸调整
相机位置、`lookAt()` 目标、正交视野和裁剪距离；本例的数值仅针对这些小方块。

`near` 和 `far` 都是相机前方的正距离，本例为 0.1 和 30。
`maxVertices=64` 容纳每个 BoxGeometry，`maxObjects=12` 容纳场景与灯光。
`Busy` 表示此次显示暂忙，下一帧重试；其他错误会打印状态并停止绘制。

父对象先声明，网格声明在几何和材质之后；所有场景和资源对象保持到应用结束。
循环只更新旋转、读取串口和提交现有画布，不逐帧创建资源。
